# 开局数据规范（src/data/raw/*.json）

本文件是开局数据的唯一格式约定。生成数据必须严格遵守，并用
`node tools/check-openings.mjs <你的文件>` 校验到 **0 错误** 为止。

## 顶层结构

```json
{
  "category": "open",
  "openings": [ /* 见下 */ ]
}
```

`category` 只能取以下五个值之一（一个文件只放一个分类）：

| 值 | 含义 | 首步特征 |
|---|---|---|
| `open` | 开放性开局 | 1.e4 e5 |
| `semi-open` | 半开放性开局 | 1.e4，黑方不走 e5 |
| `closed` | 封闭性开局（后兵开局） | 1.d4 d5 |
| `indian` | 印度防御体系 | 1.d4 Nf6 |
| `flank` | 侧翼开局 | 1.c4 / 1.Nf3 / 1.b3 / 1.f4 / 1.g3 等 |

## 开局对象

```json
{
  "id": "italian-game",
  "eco": "C50",
  "name": "意大利开局",
  "nameEn": "Italian Game",
  "summary": "一句话说明这个开局的目标与局面特点（40–80 字）。",
  "ideas": {
    "white": ["白方要点 1", "白方要点 2", "白方要点 3"],
    "black": ["黑方要点 1", "黑方要点 2", "黑方要点 3"]
  },
  "startMoves": ["e4", "e5", "Nf3", "Nc6", "Bc4"],
  "lines": [ /* 见下 */ ]
}
```

字段要求：

- `id`：kebab-case 英文，全局唯一。
- `eco`：`A00`–`E99` 格式（不确定时给最接近的常用代码）。
- `name`：中文常用译名；`nameEn`：英文标准名。
- `summary`：中文，40–80 字。
- `ideas.white` / `ideas.black`：各 2–4 条，中文，每条 15–60 字，讲战略目标而非空话。
- `startMoves`：该开局的标志性走法序列（至少 2 步），每条线路都必须以它开头。

## 线路对象

```json
{
  "id": "giuoco-pianissimo",
  "name": "平稳变例（Giuoco Pianissimo）",
  "level": 1,
  "moves": ["e4", "e5", "Nf3", "Nc6", "Bc4", "Bc5", "d3", "Nf6", "Nc3"],
  "comments": ["占据中心", "对称应法", "……（与 moves 等长）", "…", "…", "…", "…", "…", "…"],
  "keyIdea": "这条线路双方各自想要什么（一到两句）。"
}
```

字段要求：

- `level`：`1` 入门 / `2` 进阶 / `3` 高级。
- `moves`：**标准 SAN**，从起始局面开始走，长度 4–24 步（2–12 回合）。
  - 王车易位写 `O-O` / `O-O-O`（大写字母 O，不是数字 0）。
  - 升变写 `e8=Q`。
  - 将军写 `+`，将杀写 `#`（引擎会自动核对，写错会报错）。
  - 吃过路兵、双步、易位等都会逐步校验。
- `comments`：**长度必须与 moves 完全一致**，每步一条中文讲解（8–70 字），要具体：
  - 好例子：「Bc4」「瞄准 f7 弱点，同时准备 d3、c3 建立中心。」
  - 坏例子：「出子」「好棋」「正常发展」——太笼统，不要这样写。
- 同一条线路的最后一步不能停在一个明显错误的局面；线路应是真实棋谱中的常见走法序列。
- 同一开局内 `id` 不重复；不同线路的最终局面不得完全重复。

## 质量要求（很重要）

1. **准确性优先**：只写你确实熟悉的经典变例。宁可比别人少写两条线路，也不要编造走法。
2. 每个开局 **2–5 条线路**，覆盖：主线（level 1）、一个常见变例（level 2）、一到两个进阶/陷阱变例（level 3）。
3. 线路之间应体现真实的分歧点（例如白方第 6 回合的不同选择），不要只是同一线路的重复。
4. 中文术语保持一致：白方/黑方、王翼/后翼、长易位/短易位、牵制、叠兵、悬兵、中心、发展、出子、兑子、兵形、空间。

## 自查流程（必须执行）

```powershell
node tools/check-openings.mjs src/data/raw/<你的文件名>.json
```

必须迭代到输出 `✅ 校验通过（0 错误）`。警告也应尽量消除（例如走法数为奇数的线路）。

```json
{
  "category": "open",
  "openings": [
    {
      "id": "example-opening",
      "eco": "C20",
      "name": "示例开局",
      "nameEn": "Example Opening",
      "summary": "这是一个用于说明格式的最小示例，展示 startMoves 与 comments 的对应关系。",
      "ideas": {
        "white": ["白方要点一，说明战略目标。", "白方要点二。"],
        "black": ["黑方要点一。", "黑方要点二。"]
      },
      "startMoves": ["e4", "e5"],
      "lines": [
        {
          "id": "example-main",
          "name": "主线",
          "level": 1,
          "moves": ["e4", "e5", "Nf3", "Nc6"],
          "comments": [
            "白方占据中心，打开象与后的线路。",
            "黑方对称占据中心，保持局面平衡。",
            "攻击 e5 兵，同时准备短易位。",
            "保护 e5 兵，并发展后翼马。"
          ],
          "keyIdea": "双方争夺中心，白方稍占先手。"
        }
      ]
    }
  ]
}
```
